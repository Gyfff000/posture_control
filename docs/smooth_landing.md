# 平滑轨迹与软着陆改进实验

日期：2026-10-11。

基于文献：**Autonomous Landing on a Moving Platform Using Vision-Based Deep Reinforcement Learning**，Pawel Ladosz 等，IEEE Robotics and Automation Letters，2024，DOI：[10.1109/LRA.2024.3379837](https://doi.org/10.1109/LRA.2024.3379837)。

本实验建立在本仓库的示范辅助 DrQ-v2 实现上，新增指令记忆、动作平滑损失、指令 jerk 限制与接触速度奖励。它是改进实验，不是论文原方法的完整复现；长期训练尚未完成，不能声称已学出稳定的理想曲线。

## 1. 已实现的改动

### 模型能够看到自己的上一条指令

原输入为 3 帧 84×84 灰度图与 21 维自身运动状态。新输入增加 9 维：上一条归一化速度指令、当前控制器施加的速度目标、当前目标加速度，总计 30 维。新增内容均属于自身指令和控制器状态，不包含平台位置、平台速度或相对位置真值。

从旧模型迁移时复制全部兼容参数，扩展输入层的新增列置零。检查已确认：初始时新旧模型对相同图像和原自身状态的动作一致。输入层形状变化后重新初始化优化器；它是迁移微调，不是完整恢复旧 replay 与随机数状态。

### 动作变化惩罚与策略平滑损失

- 每步奖励扣除 `0.10 × mean((u_t-u_(t-1))²)`，这里 u 为归一化的三维速度指令。
- 策略损失增加 `0.15 × MSE(策略输出, 上一次实际下发的归一化指令)`。
- 保留示范辅助训练：在线 DrQ 更新的 BC 权重为 3，RL 权重为 0.02，并额外执行一次示范拟合更新。
- 训练探索标准差从 0.03 逐渐降低至 0.005；独立测试完全关闭探索噪声。

这里采用上一指令作为时间平滑参照，属于简单的动作记忆正则化，不等同于完整 CAPS 算法。相关方法参考：[CAPS：Regularizing Action Policies for Smooth Control with Reinforcement Learning](https://ai.bu.edu/caps/)。

### 限制速度目标的加速度与 jerk

水平各轴目标加速度上限 2 m/s²，竖直 0.8 m/s²；水平各轴目标 jerk 上限 8 m/s³，竖直 4 m/s³。控制器按 60 Hz 更新，通过 0.10 秒速度响应常数生成期望加速度，再限制加速度变化。

这些是**目标指令**的限制，不是对无人机真实加速度与 jerk 的硬保证。真实运动仍由 PID、动力学、姿态和接触决定，必须另外测量。训练与测试均使用相同控制逻辑；原环境默认关闭这些新增选项。

### 接近平台时逐渐减速

训练示范在约 0.8 米以内，用连续 smoothstep 将下降速度从 0.35 m/s 逐渐降到 0.12 m/s，水平仍执行平台跟踪。示范标签还采用上一指令与目标指令的连续混合，系数 0.25。

高度低于 0.6 米时，对相对水平速度和过大的下降速度增加奖励惩罚；首次成功接触时另外惩罚相对速度。平台真值仅用于训练标签、奖励和评价，测试执行网络输出，未调用示范控制器。

几何降落成功沿用原判定：无人机从上方接触平台且水平包围范围完全落在平台内部。另记“软着陆”：几何成功，并且接触前相对水平速度 ≤0.20 m/s、相对竖直速度绝对值 ≤0.18 m/s、roll/pitch 绝对值均 ≤10°。这是首次接触质量指标，尚未验证接触后长时间停留。

## 2. 已完成的初步比较

旧模型：`runs/guided_long_20261010_231249/seed_11/best_stage2.pt`。这是第一轮训练的较好阶段检查点，原第一轮已完成 60000 步。旧第二轮切换前的 6000 步模型另存为 `runs/guided_long_20261010_231249/seed22_before_smooth_switch.pt`。

新模型初始化：迁移旧模型后，用 24 次训练示范（共 5157 个样本）进行 1200 次示范拟合更新，保存为 `runs/smooth_prepare_seed31/initial.pt`。24 次示范都满足软着陆标准，这是训练数据的成绩，不能算成网络成绩。

以下网络测试使用相同的 5 个种子 `70001–70005`，全部无探索噪声。新模型此时还没有做后续在线强化微调。初始位置、平台速度及方向的采样相同；控制层与训练方法不同。

| 测试条件 | 模型 | 成功 | 软着陆 | 平均飞行 jerk RMS（m/s³） | 平均接触下降速度绝对值（m/s） |
|---|---|---:|---:|---:|---:|
| Stage 1：高度 1.5±0.3 m，平台 0–0.3 m/s | 旧模型 | 5/5 | 0/5 | 13.50 | 0.335 |
| 同上 | 新初始化模型 | 3/5 | 1/5 | 6.99 | 0.101 |
| Stage 2：高度 2.5±0.5 m，平台 0–0.5 m/s | 旧模型 | 4/5 | 0/5 | 16.43 | 0.267 |
| 同上 | 新初始化模型 | 2/5 | 0/5 | 7.70 | 0.095 |

**初步结论：加速度变化减小、下降接触变缓；成功率同时下降，尚不能认为总体性能改善。** Stage 1 的归一化动作变化 RMS 约为旧 0.117、新 0.118，并未改善；真实 jerk 的下降包含控制器限制的作用。仍有横向振荡、丢失视野和平台边缘接触，需要继续微调恢复跟踪能力。

每组仅 5 次，属于开发阶段检查，不能支持统计显著性结论。这是整套改动的比较，不是模块消融。`70001–70005` 已用于查看结果，不应再称作最终封存测试集；后续最终测试应另外使用未参与选择的种子，例如 `91001` 起。

### 在线微调 1000 步后的开发检查

从正在运行的训练中保存了独立的 1000 步快照，在相同 Stage 1、相同 5 个开发种子上再次关闭噪声测试：成功 **2/5**，软着陆 **1/5**，平均真实 jerk RMS **6.98 m/s³**。动作变化 RMS 降至约 **0.085**，但成功率尚未恢复；不能把当前改动描述成已经解决平滑且稳定降落。继续训练时会用更大的 20 次固定验证集选择模型，并保留所有失败记录。

原始数据：[1000 步开发对比](results/smooth_1000_comparison.json)、[快照来源](results/smooth_1000_provenance.json)。这次仅检查正在训练的 Stage 1，没有重复更高难度测试；该快照没有替换长期训练模型。

指标说明：轨迹按策略频率 30 Hz 记录实际位置、实际速度、控制目标与指令加速度；真实加速度及 jerk 由实际速度差分得到。为排除撞击脉冲，差分指标排除最后一个终止采样。平均接触速度统计所有有平台接触记录的飞行，包含边缘接触，未接触的失败不参与该项平均；不能只看接触速度判断任务成功。不同飞行的 jerk 先各自求 RMS，再对飞行求均值，飞行时长不同是比较的局限。

原始结果：[初始模型完整对比 JSON](results/smooth_initial_comparison.json)。检查记录：[迁移、梯度、记忆重置、jerk 限制与无示范测试检查](results/smooth_checks.json)。所有飞行 CSV 与轨迹图保存在本机 `runs/smooth_initial_comparison/`。

## 3. 已启动的长期训练

为恢复稳定跟踪能力，先固定在 Stage 1 的低速移动平台任务上训练，上限 60000 个新增交互步，每 5000 步独立测试 20 次。此轮**不自动升级难度**，因此连续验证的任务分布一致；它不代表已经解决 10 米高度、1 m/s 平台的原始任务。

- 固定验证种子从 `80001` 起，训练种子为 41。
- 保存 `latest.pt`；验证时依次按成功数、软着陆数、更低 jerk 选择 `best.pt`。
- 提前停止规则：连续三次完整的 20 次验证，成功率均 ≥80%、软着陆率均 ≥60%，且三次成功率极差 ≤5 个百分点。
- 这是实用的性能停止规则，不是数学上的收敛证明，也没有单独的 jerk 达标门槛；平滑指标仍需与成功率一起复核。
- 当前训练先按用户要求在累计 15071 步保存停止，新增[近距离预测保持与动作约束](near_landing_assist.md)并完成无训练检查后，收到明确开始指令，已恢复到 `runs/smooth_near_20261011_141534`。此前成绩不能算成新方法的结果。

训练输出目录写在 `runs/current_smooth_training.txt`。每次训练的真实轨迹保存为 `train_episode_XXXX.csv`；训练与验证日志分开保存。不要将训练中的成功率直接当作独立测试成功率。

## 4. 桌面观看

新增[平台中心预测与奖励说明](platform_center_marker.md)：完整检测失效或仅部分可见时，每个控制步进行历史位置/速度预测，置信度随丢失时间下降；最多 2 秒，低置信度提前失效。绿色为相机估计，橙色为预测；估计不是网络内部输出，不直接输入策略。启用 `--prediction-guidance` 后，检测失效分支改用置信度加权的水平接近预测中心奖励。此前 13198 步切换显示版本，本次再保存检查点继续；活动目录以 `runs/current_smooth_training.txt` 为准，旧日志和权重保留。新奖励的性能仍待验证，旧成绩不能算成它的结果。

窗口标题为 **SMOOTH VISUAL LANDING TRAINING**。

- 三个小视图分别显示真实无人机、平台、机载相机。
- 独立 PyBullet 三维窗口用蓝色线条记录本次飞行的实际路径；每次重新开始任务，路径重置。
- `3D: overview` 观察整体路径；`3D: drone` 观察无人机模型。
- 验证时显示测试组、飞行编号、仿真时间，训练更新暂停，验证完成自动继续。
- `Pause` 暂停，`Stop and save model` 保存并退出。
- 正常训练结束后窗口保留，可执行无参数更新的模型测试。保存模型并不意味着训练已成功。

桌面入口：`启动平滑降落训练.cmd`。代码已用记事本打开为 `landing_repro/smooth.py`。

## 5. 在当前已安装的 WSL 环境中重跑

以下命令假定已经完成仓库中的 CPU 环境安装，并拥有上述旧模型检查点。模型、示范数据及长期运行日志未上传 GitHub，避免将大文件混入源码；在全新电脑上须先按辅助训练指南生成旧模型，或拷贝本机检查点。

```bash
cd /mnt/d/paper_reproductions/posture_control
source "$HOME/miniforge3/etc/profile.d/conda.sh"
conda activate landing-drqv2
export LIBGL_ALWAYS_SOFTWARE=1 LP_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2

# 实现检查，不是性能实验
python -m landing_repro.check_smooth

# 生成新输入下的示范并迁移预训练
python -m landing_repro.smooth prepare \
  --checkpoint runs/guided_long_20261010_231249/seed_11/best_stage2.pt \
  --output runs/smooth_prepare_seed31 --episodes 24 --bc-updates 1200 --seed 31

# 同条件无噪声开发测试与实际轨迹图
python -m landing_repro.smooth benchmark \
  --baseline runs/guided_long_20261010_231249/seed_11/best_stage2.pt \
  --checkpoint runs/smooth_prepare_seed31/initial.pt \
  --output runs/smooth_initial_comparison --episodes 5 --stages 1 2 --seed 70001

# 开始实时训练；已有本入口启动的训练时，会防止重复启动
bash start_smooth_training.sh
```

重跑准备和对比命令会覆盖同名输出，保留旧实验时请改成新的目录，并在启动训练时同步修改数据路径或使用 `smooth train` 的完整参数。长期模型加载兼容 30 维输入，旧的 21 维评估入口不适用于这类模型，应使用 `smooth benchmark` 或新窗口的测试功能。
