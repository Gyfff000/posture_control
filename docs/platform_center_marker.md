最新扩展：[近距离中心保持与小幅动作](near_landing_assist.md)。启用 `--near-landing-assist` 时，满足可靠近距离条件后预测最多 8 秒，并使用缓慢的置信度衰减、估计反馈及动作约束；下面的 2 秒规则描述未启用该扩展的通用模式。训练先在 15071 步保存停止，检查完成并收到用户明确开始指令后，已恢复到 `runs/smooth_near_20261011_141534`。

基于文献：**Autonomous Landing on a Moving Platform Using Vision-Based Deep Reinforcement Learning**，Pawel Ladosz 等，IEEE RA-L 2024，DOI：[10.1109/LRA.2024.3379837](https://doi.org/10.1109/LRA.2024.3379837)。以下是本仓库新增的辅助训练实验，属于对原方法的改动。

## 1. 什么时候预测

估计器在每个策略控制步更新，频率 30 Hz，与界面刷新无关，无窗口训练和测试也执行同一逻辑。

| 情况 | 处理 | 桌面标注 |
|---|---|---|
| 完整标识通过模板、PnP 和滤波创新检验 | 用观测修正位置、速度 | 绿色 VISION |
| 平台只露出部分、外框被裁切、低质量检测或检测完全丢失 | 下一控制步立即从历史状态外推 | 橙色 PREDICTED |
| 从未取得可靠观测，或预测过期、置信度过低 | 中心未知，不用真实坐标替代 | CENTER UNKNOWN |

预测不要求相机里的平台像素完全消失。只要无法得到可靠的完整标识位姿，即使仍看见一部分平台，也进入预测。启用预测奖励的版本要求模板一致性分数至少 0.45；旧显示版本沿用 0.35。

**必须先有可靠观测，才能从历史推测位置。** 当前版本没有实现从一张首次出现的残缺平台图像直接恢复完整平台。重新可靠检测后恢复观测更新。

## 2. 位置和置信度怎样计算

1. 从原始 84×84 RGB 提取深色轮廓，连接细边框的断续点，寻找完整凸四边形。
2. 与已知圆圈 H 标识进行模板检验；用已知 1 米尺寸和相机内参做 PnP。
3. 用相机安装位姿、自机位姿转换为世界坐标，再用位置—速度线性卡尔曼滤波平滑。
4. 没有可靠观测时：`预测位置 = 上次滤波位置 + 估计速度 × 时间间隔`。

置信度采用明确的时间衰减规则：

```text
C(t) = Q_last × exp(-Δt / 0.85)
```

`Q_last` 是上次接受观测的模板一致性分数，`Δt` 是距该观测的仿真时间。若 Q_last=0.8，则 0、0.5、1、1.5 秒的 C 约为 0.80、0.44、0.25、0.14。超过 2 秒，或 C<0.10，均停止使用并隐藏预测，因此可能在 2 秒之前失效。

这是工程上的可信程度指标，**不是“位置正确的概率”**。同时记录卡尔曼位置标准差 `position_std_m` 作为诊断，但本轮时间衰减公式没有用它校准概率。

估计器没有读取平台分割 ID、真实位置或真实速度。它使用仿真自机位姿完成坐标变换，本轮没有加入自机定位噪声；未知平台加速、转弯、低分辨率和位姿误差都会影响预测。外部近景相机利用平台真值取景，和标线估计来源不同。

## 3. 有没有靠近预测中心的奖励

**旧显示版本没有；新增 `--prediction-guidance` 版本有。**

当前检测失效或不完整、且预测有效时，替换原先基于平台真值的稠密距离引导项，使用：

```text
r_prediction = 4 × C × clip(d_before - d_after, -0.10, 0.10)
```

`d_before` 和 `d_after` 都是自机到同一个外推中心的水平距离。靠近为正、远离为负、悬停为零。两次距离使用相同目标，避免平台移动或检测跳变本身给无人机加分。置信度降低，奖励和惩罚同步减弱；没有有效预测则此项为零。

此分支不使用平台真值计算引导距离，也没有新增预测期间的下降奖励。保留每步成本、动作平滑惩罚，以及现有物理接触/碰撞结局与软着陆质量项；后者仍是仿真训练奖励，不能把整个任务称为无真值训练。

原来平台完全不可见 1 秒会结束回合；现在只在预测仍有效时延长这段容忍时间，预测过期且已经完全不可见至少 1 秒就结束。若仍有平台像素但中心未知，停止预测奖励，继续受原回合时限约束。

策略输入仍是 3 帧图像和 30 维自身状态/指令记忆，**预测中心、置信度没有直接输入网络，也没有用估计器替换网络动作**。所以这是奖励改进，不等于已训练出能长时间盲跟踪的策略。在线示范纠错只在完整检测被接受时收集；旧示范数据保留。

## 4. 桌面与日志

竖线在世界坐标中向上延伸 1 米：绿色为观测，橙色为预测，蓝线为实际飞行轨迹。三个小视图显示同一竖线的投影；正下视时可能接近一个点。

界面显示 `C`、距上次完整检测的时间、`Prediction reward` 和 `Guidance: ON/OFF`。所有标注画在图像副本或 PyBullet 调试层，原始策略图像没有线、十字或文字。

`live_status.json` 包含 `center_estimate`、`prediction_reward`、`prediction_guidance`。每回合 CSV 新增估计中心、置信度、年龄、预测奖励、模式编号（观测 1、预测 0、未知 -1）及平台像素是否可见；回合总结记录预测帧数和预测奖励累计值。

## 5. 已验证什么

运行：

```bash
python -m landing_repro.check_prediction
python -m landing_repro.check_center_marker
python -m landing_repro.check_smooth
```

- 真实渲染图像裁切后，在首个控制步进入预测，即使平台像素仍可见。
- 预测置信度按时间下降，重检测恢复；过期不返回真实中心。
- 靠近奖励约 +0.048，远离 -0.048，悬停 0；置信度减半则奖励减半。这是固定几何输入的逻辑检查。
- 无界面相机漏检检查中，预测持续更新，允许超过旧的 1 秒漏检限制，约 1.37 秒后因置信度不足正常终止。
- 原始图像不受标注影响；30 维模型保存、加载、梯度和旧配置兼容检查通过。

这些是实现检查，人工裁切/空白帧仅用于检查，未作为真实网络成功率。记录见 [预测与奖励检查](results/prediction_checks.json)、[相机中心检查](results/center_marker_checks.json)、[平滑模型检查](results/smooth_checks.json)。

## 6. 保存原训练后继续

当前训练路径始终由 `runs/current_smooth_training.txt` 指向。新训练保留模型权重、优化器和累计步数；当前半个回合、经验缓存、在线样本及随机数状态重置，因此不是逐位一致恢复。奖励任务改变后验证排名重新开始，旧最佳模型另存 `previous_task_best.pt`，不混为新方法结果。

本次在累计 **14679** 步保存并切换，新目录为 `runs/smooth_prediction_20261011_135604`，来源为 `runs/smooth_center_20261011_133916/interrupted.pt`。界面累计成功数包含之前训练，不是新奖励方法的独立结果。已确认新窗口 `prediction_guidance=true`、实际出现非零预测奖励，并继续发生参数更新。

已有本项目训练正在运行时，在仓库根目录、已激活的 WSL Python 环境中，可以执行一次以下入口：

```bash
python -m landing_repro.resume_smooth
```

它核对活动进程、保存中断检查点，再前台重开带预测奖励的桌面训练。没有匹配的活动进程会报错，不随意终止其他进程。不要重复执行；桌面启动脚本也会阻止重复训练。

手动恢复可用 `smooth train` 的 `--checkpoint`、`--step-offset`、`--resume-run` 和 `--prediction-guidance`。省略最后这个开关时继承检查点设置；`--no-prediction-guidance` 可关闭用于后续对照。当前尚无新奖励方法的独立成功率结论，需与关闭版本在相同测试条件下比较。
