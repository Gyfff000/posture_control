# 桌面平台中心竖线：视觉观测与漏检预测

更新日期：2026-10-11。基于本项目对 **Autonomous Landing on a Moving Platform Using Vision-Based Deep Reinforcement Learning**（Pawel Ladosz 等，IEEE RA-L 2024，DOI：10.1109/LRA.2024.3379837）的辅助训练改进实验。

## 如何看标线

- **绿色竖线 / VISION center**：辅助视觉检测器在当前原始相机图像中识别出平台标识，经过滤波估计的中心。
- **橙色竖线 / PREDICTED**：当前没有可靠检测，使用之前的位置与速度做匀速预测。旁边的秒数表示距上次可靠观测的仿真时间。
- **CENTER UNKNOWN**：尚未检测到中心，或距上次观测已超过 2 秒。此时隐藏标线，不用真实平台坐标冒充预测。
- 蓝色线仍表示无人机实际飞行轨迹。

竖线在世界坐标中竖直，从估计中心向上延伸 1 米。三维窗口能直接看到；三个小视图显示同一根世界竖线的投影，并在中心画十字。相机正好向下对准竖线时，它的投影可能很短或接近一个点，这是投影关系，不代表没有标注。

**当前策略是“图像与自身状态 → 速度”，没有显式的平台中心输出。新增标线是独立的显示辅助估计，不是网络注意力或网络内部预测的可视化，也没有接入策略控制。**

## 估计来自哪里

代码：`landing_repro/center_marker.py`。

1. 在原始 84×84 RGB 相机图像中提取深色轮廓，连接细边框因低分辨率产生的断续点。
2. 寻找完整凸四边形，并用已知的圆圈 H 标识设计进行模板一致性检查。
3. 根据已知 1 米标识尺寸、相机内参进行 PnP 位姿求解，再用相机相对机体安装位姿和自机位姿转换到世界坐标。
4. 用位置—速度线性卡尔曼滤波平滑观测；漏检时按匀速模型推进，最多显示 2 秒。

检测函数没有读取平台分割 ID、平台位置或平台速度。世界坐标变换使用仿真中的自机位姿；本轮没有加入自机定位噪声。外部近景相机仍利用真实平台坐标构图，这只是观察窗口的取景，标线的位置由上述独立检测/预测决定。

绿色表示“检测通过”，不表示坐标精确。模糊、很远、外框被裁切或仅有部分平台可见时可能无法检测；因此策略仍能看到一些平台像素时，标线也可能变成预测状态。模板一致性分数不是经过校准的概率。匀速预测也可能偏离真实平台，不能据此声称模型具备漏检控制能力。

## 显示不改变模型输入

只在显示图像的副本上绘制线和文字；三维竖线使用 PyBullet 调试线，没有增加实体、碰撞体或平台识别标签。原始 `env.rgb` 与策略帧堆叠保持原样。原来的训练奖励、动作、参数结构、探索策略和漏检终止规则均未改变。

状态文件 `live_status.json` 新增 `center_estimate`，包含 `observed / predicted / unknown`、估计坐标、估计速度、距上次观测时间和来源说明。验证阶段也会显示该验证环境的中心估计；独立 PyBullet 窗口此时保留训练世界，桌面文字会说明这个区别。

## 验证与上线

执行 `python -m landing_repro.check_center_marker`：

- 真实渲染相机单例中心三维误差约 **0.106 m**，平台真值仅用于这个检查的误差评分，未作为检测输入。
- 人为提供 0.4 秒空白帧后进入橙色预测，预测位置等于“先前位置＋先前速度×时间间隔”。
- 超过 2 秒隐藏不可靠预测，新回合清空记忆。
- 确认绘制前后原始模型图像不变。

空白帧检查是独立的小测试，没有在真实训练中人为遮挡相机；一例误差也不能代表全面检测精度。检查 JSON 见 [原始检查记录](results/center_marker_checks.json)。本机示例图保存在 `runs/center_marker_checks/observed.png` 与 `predicted.png`，后者明确标为人工漏检检查。

为让当前窗口立即加载标注，保存了旧训练的 `interrupted.pt`，在总步数 **13198** 处重开窗口。模型权重、优化器、回合累计成绩、历史验证及最好的检查点均保留；当前部分飞行、经验缓存和在线示范缓存重置，随机数重新设种子，因此不是逐位完全一致的恢复。

当前目录：`runs/smooth_center_20261011_133916`；上一段目录：`runs/smooth_long_20261011_124808`。当前总步数仍以 60000 为上限，指针仍为 `runs/current_smooth_training.txt`。

